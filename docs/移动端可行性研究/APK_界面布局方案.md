# LifeOS Android 界面布局方案（五 Tab 版）

> 一级导航已定为**底部 5 Tab：设置 / 健康中心 / 财务中心 / 生活中心 / 投资中心**，Tab 是唯一一级导航。
> 本文推翻前几版"抽屉唯一""4 Tab + 抽屉 + 首页""首页单中枢"的结论；旧 A–E 对比只保留在附录 A 作为推导痕迹，不作为结论。
> 只做设计，不写代码、不建工程；技术栈、打包、运行时、合规、分发见 `APK_开发方案.md`。未实测项标「待验证」。

## 0. 结论

| 项 | 结论 |
|---|---|
| 一级导航 | **底部 5 Tab，唯一一级导航**；不做抽屉、不做汉堡菜单、不设首页中枢 |
| Tab 顺序 | 健康 / 财务 / 生活 / 投资 / 设置（设置放最右，见 §4.2） |
| 首页 | **取消**。今日待办与关键指标下沉到各 Tab 首屏头部；跨域待办由铃铛进入"通知中心"承接 |
| 启动落地 | 冷启动固定落第一个 Tab「健康中心」；从后台返回保持当前 Tab；深链直达目标页 |
| 全局浮层 | 只有两个：每个 Tab 根页顶栏的**铃铛**、每个 Tab 根页右下角的**全局「＋」FAB** |
| 页面总量 | **30 个**（现有路由页 28 + 登录/首启动 2）；手机端实装 **28**（§2.3） |
| 工作量 | **23–31 人日**（相对上一版 21–29 净 +1.5 ~ +2.5，§7） |

口径修正：上一版"27 页（业务 25 + 入口 2）"与 `frontend/src/config/routes.ts` 不符。逐条清点为 29 条路由（其中 1 条是兼容重定向），去掉被取消的首页 = 28，加 2 个登录前页面 = **30**。§2.1 逐条列出，不留估算。

## 一、这个结构自带的三道必答题

### 1.1 问题一：首页 / 今日主线没有位置

三个候选，选 **(i) 取消首页，域内首屏承担今日主线**，落地规则用 (ii) 的变体。

| 候选 | 做法 | 判断 |
|---|---|---|
| (i) 取消首页，各 Tab 首屏头部放该域待办 + 指标 | 健康首屏有"今日用药"、财务首屏有"到期账单" | **主选** |
| (ii) 固定落地某一个 Tab 承担今日主线 | 每次打开 App 都在同一个域 | 只采纳其"落地"部分，不采纳"单一页面扛全部待办" |
| (iii) 某 Tab 顶部加横滑摘要卡 | 在域内塞跨域摘要 | 否掉 |

**为什么是 (i)**
- 待办天然有域属性：用药属于健康、账单属于财务、体检属于健康、物品到期属于生活。把"今日待办"拆回各自域内，点进去就是可执行动作（勾选/打卡/还款），比在首页列一堆再跳转少一步。
- 5 Tab 结构里每个 Tab 根页本来就需要"概览"，今日待办正好成为概览的头部，不额外占页面。
- 冷启动固定从第一个 Tab（健康中心）开始，域内首屏头部就是该域今日待办；回到后台再从原 Tab 继续。

**代价（必须认）**
1. 没有"一眼看今天所有事"的单页视图。跨域待办只能进通知中心看（铃铛 + 角标）。
2. 首次使用者打开 App 直接进健康中心，域内首屏只覆盖健康一件事，缺少一个解释"这个 App 有 5 个域"的落地页 → 靠首启动引导页（登录前那一页）承担一次介绍职责。
3. 每个 Tab 都要做一块"待办头部"，5 份而不是 1 份，实现与走查成本上升。

**落地规则**
- 冷启动固定落 **健康中心**（第一个 Tab）：横向五个域并列，没有任何一个域能天然代表"这个 App"，硬挑一个会让另外四个被误认为次要；健康是每日最稳定的动作（打卡/体重/步数），落第一屏最容易被继续使用。
- 从后台返回（进程未被杀）→ **保持当前所在 Tab 与页面**，不强制跳回健康中心；用户在某域做事，回来还在原处。
- 从系统通知 / 深链点入 → 直达对应页面，不被默认落点覆盖。
- 不做"上次停留 Tab"的本地持久化：冷启动口径唯一，避免两套行为互相打架。

**为什么否掉 (iii) 横滑摘要卡**：摘要卡要横滑，就与页面内的筛选 chips、图表横滑抢同一个手势区；而且它只能在某一个 Tab 出现，等于把"首页"偷偷改名塞回来，与"5 Tab 全是业务域"的定义冲突。否掉 (ii) 的"单页扛全部"：打开总是同一个域，另外 4 个域的待办每次都要人肉找，且长期会让用户以为 App 只有那一个模块。

### 1.2 问题二：「设置」作为一级 Tab 与自身低频的矛盾

保留这个 Tab，但把它从"配置页"改造成 **设备与账户的仪表盘 + 配置入口**：首屏先回答"我的数据通路是否正常"，再往下才是配置。

**设置 Tab 完整目录（收进来的）**

```
┌ 设置（Tab 根页）
├─ ① 账户卡
│   ├─ 头像 / 昵称 / 当前服务器            → 账户设置
│   ├─ 退出登录                             （危险区，见 §5.5）
│   └─ 登录设备（会话管理）                 → 二级：设备列表 + 单台下线
├─ ② 状态区（首次进入必看，来自系统真实状态）
│   ├─ 服务器连接  ●已连接/○不可达 192.168.1.8:9515  → 地址与连接测试
│   ├─ 提醒权限    已开启 / 去开启（跳到系统设置）
│   ├─ 本地通知     [开关]
│   └─ 数据同步时间 3 分钟前
├─ ③ 提醒与渠道
│   ├─ 邮件提醒 [开关]  / 钉钉 / 飞书 / 企微 / TG / Webhook  （渠道开关，非配置密钥）
│   └─ 提醒时间说明（后端扫描时间，只读）
├─ ④ 数据与连接
│   ├─ 服务器地址与连接测试
│   ├─ 数据备份                       → 二级：仅"导出下载"（JSON/SQL/ZIP）
│   ├─ 清除本地缓存
│   └─ 检查更新（versionCode 对比）
├─ ⑤ 系统管理（仅管理员，默认折叠）
│   ├─ 活动日志            → 三级「安全与日志」
│   ├─ 安全审计            → 与活动日志合并为 1 页，顶部分段切换
│   ├─ 系统设置（站点配置） → 二级「高级」，手机端只读
│   └─ 数据备份（同上，管理员可见全量）
└─ ⑥ 关于：版本号 / 隐私说明 / 开源许可
```

**推到别处去的（不占设置 Tab）**

| 内容 | 去处 | 理由 |
|---|---|---|
| 用药/账单/体检的提前提醒 | 各详情页字段 | 提醒是数据属性，不是设备配置 |
| 通知列表本身 | 顶栏铃铛 → 通知中心 | 每天要看，不能埋在设置里 |
| 恢复导入（上传备份文件） | 桌面端 | 手机选文件 + 长时间阻塞 + 覆盖风险，1 年内可能用不到 |
| 系统设置中的站点级参数（如扫描时间、渠道密钥） | 桌面端 | 改错会全局失效，手机端只读展示 |
| 会话管理独立页 | 并入「设置 → 登录设备」 | 同类信息重复，1 页足够 |

**代价（照实写）**
- 5 个 Tab 里最不该占黄金位的正是设置：它月频甚至季频，却与"每天多次"的财务、健康平分 1/5 屏幕。**最高频的"记一笔"因此要多一步切 Tab**（补偿：全局 FAB 常驻，把这一步压成 0）。
- 代价换来的收益是：5 Tab 每格语义都完整（不含"我的"这种垃圾桶 Tab），并且账户/设备/权限/更新有了稳定的家，不用再去别的域找。
- 若未来设置内容继续膨胀，扩容路径是把 ⑤ 折叠成"高级"分组，而不是再加 Tab。

### 1.3 问题三：通知中心与账号入口

| 项 | 结论 |
|---|---|
| 铃铛位置 | **每个 Tab 的根页顶栏都放**，右侧，带未读角标；二级页顶栏不放（让位给返回 + 标题 + 页内动作） |
| 通知中心归属 | 不属于任何 Tab，是全局目的地；从 5 个 Tab 根页均 1 步进入；返回回到进入前的 Tab |
| 账号切换 / 退出 | **收进设置 Tab 首屏账户卡**；不在每个 Tab 顶栏放头像 |
| 设置内账号区 | 账户卡（昵称 + 服务器）→ 账户设置页；退出登录在页尾危险区；切换账号 = 退出后重新登录（后端无多账号切换接口「待验证」） |

理由：铃铛是"随时要看、且跨域"的信息，必须每个域都能一步到；账号是"几乎不看"的东西，放在设置里刚好消化一个低频入口。顶栏如果同时放头像和铃铛，右侧会挤成两个热区，误触率上升。

### 2.2 跨域页面的归属规则（判断依据）

| 页面 | 归属 | 判断依据 | 反例（为什么不放另一侧） |
|---|---|---|---|
| 账单管理 | **财务** | 账单三要素是金额、到期日、还款状态，全部围绕现金流 | 放生活会让"钱"分散在两个 Tab，财务总览的"待还"就要跨 Tab 取数 |
| 通知中心 | **全局（顶栏）** | 它是跨域收件箱，5 个域的提醒都在里面 | 归任一域，其他 4 域的提醒都变成"别人的通知"，角标也会错位 |
| 健康/财务/生活/投资报告 | **各自域内** | 报告的时间轴、图表口径、筛选条件都绑在本域数据 | 合并成"总报告"要重做取数、权限与筛选，且首屏永远是半空的 |
| 物品 / 卡片 | **生活** | 卡片现有语义是卡包（会员/门禁/证件），不是信用卡负债 | 若后续加入额度/账单字段才考虑上移财务「待验证」，当前按卡包处理 |
| 用药 / 体检 / 账单的提前提醒 | **各详情页** | 提醒是数据属性（这条药、这笔账），不是设备配置 | 集中到设置会让同一条数据两处可改，容易漂移 |
| 数据备份 | **设置** | 属设备级运维，与业务域无关 | 放任一业务域都会让另外 4 个域"备份找不到" |
| 系统设置 / 活动日志 / 安全审计 / 会话 | **设置（管理员折叠组）** | 全部是运维与合规，管理员才可见 | 若散落在各域，普通用户会看到空页或误入 |

**手机端实装 28**：
- 系统设置（#27）手机端只读，不单独做编辑页 → 减 1；
- 活动日志 + 安全审计合并为 1 页 → 减 1；

## 三、每个 Tab 的组织方式

5 个 Tab 不套同一模板：**有每日待办的域做"待办 → 指标 → 入口 → 列表"，低频域直接给入口，设置给状态 + 目录。**

| Tab | 首屏形态 | 首屏顺序（一句话） | 判断理由 |
|---|---|---|---|
| 健康 | 概览驱动 | 今日用药/体检待办 → 4 指标 → 6 模块入口 → 最近记录 | 健康是提醒驱动，漏了有健康代价；首屏必须先回答"今天要做什么" |
| 财务 | 概览 + 列表混排 | 本月支出/应还 2 卡 → 到期账单待办 → 记一笔 chips → 直接接最近流水列表 | 录入最高频，首屏下半必须直接是流水（可滚动找上一笔），模块入口压缩成一行 chips |
| 生活 | 入口列表，不做指标 | 3 个模块行（物品/卡片/报告，每行一行摘要）→ 近期变动 | 低频域做指标是空屏；用户来这里目的明确（找东西/找卡） |
| 投资 | 概览驱动 | 持仓/浮盈 2 卡 → 风险提示（如仓位/单笔超限）→ 3 个模块入口 → 最近交易 | 数值驱动，先看数字再看明细 |
| 设置 | 状态 + 目录 | 账户卡 → 4 个状态行（连接/通知权限/本地通知/同步时间）→ 分组目录 | 低频 Tab 靠"设备状态"制造每天都可能瞄一眼的理由，否则长期是空页 |

### 3.1 健康 Tab 首屏

## 四、Tab 栏规格与可用性推算

### 4.1 M3 NavigationBar 规格

| 项 | 规格 | 依据 |
|---|---|---|
| 高度 | 80dp（含底部手势条 inset 时实际总高 = 80 + inset） | M3 NavigationBar 标准高度 |
| 图标 | 24dp，选中/未选中同一尺寸（不改尺寸只改色与指示器） | M3 规范，尺寸跳变会抖动 |
| 标签 | 12sp，单行，`maxLines=1`，选中加粗一档 | M3 label 12sp |
| 选中指示器 | 64×32dp 胶囊，圆角 16dp，位于图标层，不覆盖标签 | `placeholder` 由组件库提供「待验证」精确值 |
| 动效 | 指示器位移/淡入 300ms（M3 fade-through 口径）；页面内容切换 300ms 淡入 | 只切内容不做滑动位移，避免 5 Tab 左右滑产生方向错觉 |
| 点击热区 | 每格宽度即热区（375 屏 = 75dp ≥ 48dp 最小触控） | Material 触控下限 |
| 角标 | 仅"设置"格显示小红点（来自铃铛未读汇总，可选）「待验证」 | 避免 5 格都挂角标 |

**顺序**：健康 / 财务 / 生活 / 投资 / 设置。把设置放最右而非最左：右手单手持机时右边缘更易触达，而设置是 5 个里最不该被误点的；同时"业务在前、配置在后"符合阅读顺序。

### 4.2 375dp 屏宽：4 字标签放得下吗

推算（375 / 5 = **75dp/格**）：

| 项 | 数值 |
|---|---|
| 单元格宽 | 75dp |
| 左右内边距（点击留白，各 8dp） | 16dp |
| 可用标签宽 | **59dp** |
| "健康中心" 4 字 × 12sp（汉字 ≈ 1em = 12dp） | **48dp** |
| 余量 | +11dp |

**结论：1.0x 字号下放得下（48 ≤ 59），但只剩 11dp 余量，没有容错。** 一旦字体放大或系统字体略宽，就会溢出。

### 4.3 1.3x 字号：溢出，直接改用短标签

| 项 | 1.0x | 1.3x |
|---|---|---|
| 4 字宽（12sp → 15.6sp） | 48dp | **62.4dp** |
| 可用宽 | 59dp | 59dp |
| 结果 | 余 11dp | **溢出 3.4dp**（截断成"健康中…"） |
| 2 字短标签（健康/财务/生活/投资/设置） | 24dp | **31.2dp**（余 27.8dp） |

**决策：默认就用短标签**（健康 / 财务 / 生活 / 投资 / 设置），顶栏标题用全称（"健康中心"）。语义损失评估：
- "健康""财务""生活""投资" 4 个词本身已是完整域名，缩写为 2 字几乎无损；
- "设置" 无损失；
- 唯一损失是"中心"二字带来的"这是一个域集合"的暗示，由顶栏大标题和首屏内容补足。
- 因此 **不用 `ellipsis` 兜底**，短标签在 1.0x / 1.3x / 320dp 下都不溢出；`maxLines=1` 仍保留作为防御。

### 4.4 320dp 极窄屏：不降级

| 项 | 320dp |
|---|---|
| 单元格宽 320/5 | 64dp |
| 可用宽（−16dp） | 48dp |
| 4 字 @12sp | 48dp（**刚好 0 余量**，实际必溢） |
| 4 字 @15.6sp | 62.4dp（溢出） |
| 2 字 @12sp / @15.6sp | 24dp / 31.2dp（余 16.8 / 16.8） |
| 触控热区 64dp ≥ 48dp | 满足 |

**结论：320dp 只靠"短标签"就够，不需要降级成 4 Tab。** 降级的代价（把投资或生活塞进设置）远大于收益：会重新制造"垃圾桶 Tab"，且 320dp 设备占比已很低。仅当出现 <320dp（极罕见）才考虑隐藏标签只留图标「待验证」。

### 4.5 横屏与 ≥600dp

| 断点 | 处理 |
|---|---|
| <600dp（手机竖屏） | 底部 5 Tab，短标签 |
| 600–839dp（折叠屏/平板竖屏） | Tab 保留（M3 允许 NavigationBar 用于 compact/medium），内容限宽 600dp 居中；列表-详情可双栏 |
| ≥840dp（平板横屏） | Tab 换成 **NavigationRail**（5 项竖排，含标签），内容区双栏：左列表右详情 |
| 手机横屏（高度 <480dp） | Tab 保留但内容区加纵向滚动；表单页改全宽单列，避免键盘吃掉整屏 |

说明：NavigationRail 是同一个"5 项导航"的形态切换，不是第二套导航，不算抽屉复活。

## 五、页面布局规范

### 5.1 Tab 根页（原"首页"规格改写）

原"首页（今日）"已取消，其规格改为 **5 个 Tab 根页的三类模板**。共同骨架：

```
┌────────────────────────────────────────┐
│ 标题（全称 20sp）                🔔 角标│  顶栏 56dp，无返回箭头、无汉堡
├────────────────────────────────────────┤
│ 首屏区：1–2 个区块（不得更多）           │
│ ...                                      │
│ [可滚动：入口 / 列表 / 变动流]           │
│                                    (＋) │  FAB，仅根页
├────────────────────────────────────────┤
│ 健康  财务  生活  投资  设置            │  NavigationBar 80dp
└────────────────────────────────────────┘
```

| 模板 | 适用 | 首屏 → 次屏顺序 | 硬约束 |
|---|---|---|---|
| A 待办优先 | 健康 | 待办 → 指标 → 宫格入口 → 最近记录 | 待办必须有，且可原地打卡；超过 3 条折叠为"全部" |
| B 数字 + 列表 | 财务、投资 | 2 张数字卡 → 待办/风险提示 → chips → 列表 | 列表必须在首屏可见至少 2 行，否则这个 Tab 变成"看报表" |
| C 入口列表 | 生活、设置 | 账户卡（仅设置）→ 入口行 / 状态行 → 变动流 | 行使列表行高 56–72dp；不做指标卡 |

根页规则：
- 顶栏只放"标题 + 铃铛"，最多 2 个元素；不放搜索框、不放头像；
- 根页不出现"保存/提交"类操作，全部是导航型点击；
- 区块标题不吸顶（只有列表分组头吸顶），避免根页出现多层固定栏；
- 根页空数据时保留指标骨架 + 入口，禁止整屏空态（空态只用于域内列表页）；
- 数字用等宽（tabular），单位小一号、降对比度。

### 5.6 全局「＋」FAB

| 项 | 结论 | 理由 |
|---|---|---|
| 挂载范围 | **只在 5 个 Tab 根页**，二级页/表单页/通知中心隐藏 | 二级页有 AppBar 新增入口；表单页已有吸底保存条，再挂 FAB 会有三个底部热区 |
| 位置 | 右下 16dp；距屏幕底部 = Tab 栏 80 + 16 + 手势条 inset | 与 Tab 栏留 16dp，不压住"设置"格 |
| 尺寸 | 56dp（M3 标准 FAB），图标 24dp，无标签 | |
| 展开形态 | **先弹底部四选一**（记支出 / 记账单 / 记用药 / 记体重）→ 再进对应全屏表单 | 跨域记录必须从任何 Tab 都能出发；直接弹表单会猜错类型 |
| 列表留白 | 内容底部 padding ≥ **160dp**（80 Tab + 16 + 56 FAB + 8） | 保证最后一行能滚到 FAB 上方，不被遮挡 |
| 滚动行为 | 不隐藏、不缩小 | 忽隐忽现比轻微遮挡更烦；靠留白解决 |
| 否决方案 | ①只在财务 Tab 挂 → 健康域记用药要多 1 次切 Tab，T0 动作退化；②每个 Tab 各挂各的 → 5 套图标语义漂移，且根页已有入口重复 | |

### 5.7 跨场景规范

| 场景 | 规则 |
|---|---|
| 单手 | 主操作落在下 1/3：Tab 栏、FAB、保存条；顶栏右侧只放铃铛 1 个动作 |
| 安全区 | 顶栏让状态栏 inset；Tab 栏与 FAB 让手势条 inset；挖孔区左右留白；边到边 |
| 深色模式 | 跟随系统；`surface` 不纯黑；选中态与图表另配，对比度 ≥4.5:1；Tab 指示器颜色单独校验 |
| 字体 1.3x | Tab 用 2 字短标签（§4.3）；行高用最小高度；金额/标题单行省略；专项走查 5 个根页 + 表单页 |
| 空态 | 64dp 图标 + 16sp 标题 + 12sp 说明 + 主按钮；仅用于域内列表页，根页不用 |
| 加载态 | 列表 6 行骨架；按钮内联进度；下拉刷新保留旧数据（0.6 透明度）；>300ms 才显示骨架「待验证」 |

## 六、状态与返回栈

| 问题 | 结论 | 说明 |
|---|---|---|
| Tab 切换是否保留滚动位置与筛选 | **保留** | 每个 Tab 一条独立导航栈 + 根页状态保留（滚动位置、筛选 chips、搜索词）；切回时不需要重新加载 |
| 内存代价 | 5 个根页各持列表数据 | 根页列表按 20 条/页懒加载，切走不释放但禁止预取下一页；二级页在切 Tab 时**保留**栈（返回可回到原详情）「待验证」内存表现 |
| Tab 内二级页返回 | **回到该 Tab 根页** | 列表 → 详情 → 返回，回到列表并**恢复原滚动位置**（不是回到顶部） |
| 从 A Tab 跳到 B Tab 的页面 | 切换到 B Tab，在 B 的栈里 push 目标页；A 的栈**原样保留**；返回键回到 **B 的根页**，不弹回 A | 示例：健康报告里点"本月支出" → 财务报告；返回 → 财务总览，Tab 高亮停在财务。理由：若返回弹回 A，Tab 高亮会跳变，用户以为"回到健康了但内容又是财务" |
| Tab 重按（再次点击已选中） | 在二级页 → **pop 到根页**；已在根页 → **滚回顶部**；无第三次行为 | 不做"再按一次退出"，退出只在根页按返回键 |
| 系统返回键 | 二级页 → pop；根页 → 「再按一次退出」（2 秒内二次才退） | 5 Tab 之间**不**用返回键切换（避免"返回"变成"换 Tab"） |
| 表单页返回 | 有未保存改动 → 底部确认弹层；无改动 → 直接回上一页，Tab 栏恢复 | |
| 通知中心返回 | 回到**进入前的 Tab**（不是固定回财务） | 记录进入来源即可 |
| 边缘手势 | 不做自定义滑动，依赖系统返回手势 | 5 Tab 下也不需要左右滑动切 Tab（内容区无横向分页） |

**Tab 栏显隐规则汇总**：根页与列表/图表/设置子页**显示**；表单页、登录/引导页**隐藏**。这样底部最多只有一层 80dp 栏，或一层 64dp 保存条，不会叠加。
